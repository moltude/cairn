# Running and writing cairn's tests

## Before the first run

`uv run pytest` fails on a cold checkout — it falls back to a system Python and dies with ~36
`ModuleNotFoundError: No module named 'yaml'` collection errors. pytest and pytest-cov live in
`[project.optional-dependencies].dev`, which plain `uv sync` does not install.

```bash
uv sync --all-extras
```

Do this once per fresh clone and after any dependency change.

## Running

```bash
uv run pytest                                    # full suite, ~2.5min (web e2e included)
uv run pytest --no-cov tests/test_writers_tracks.py          # single file
uv run pytest --no-cov tests/test_x.py::test_name            # single test
```

Always `uv run` — never bare `pytest` or `python`.

**Pass `--no-cov` on narrow runs.** `pyproject.toml` sets
`addopts = "--cov=cairn --cov-report=term-missing"`, so a single-file run prints a full-package
coverage table showing everything as uncovered. That table is noise; only a full-suite run
produces meaningful coverage.

## The healthy baseline

**686 passed, 2 skipped** as of 2026-08-30 (Python 3.14, with the web dev server running —
`uv run python web/serve.py`; without it the 36 `tests/web` Playwright tests skip, giving
650 passed / 38 skipped). A different pass count means something
changed — find out what before continuing.

The 2 skips are disabled regressions, not environment skips
(`test_tui_filter_search.py:661`, `test_tui_keyboard_shortcuts_comprehensive.py:159`).

## Fixtures

- `tests/fixtures/bitterroots/Bitterroots__Complete_.json` — canonical large CalTopo dataset.
- `tests/fixtures/edge_cases/` — poles, dateline, unicode, XML chars, malformed input,
  10k-feature stress files. Generated by `scripts/generate_edge_case_fixtures.py`.
- `tests/fixtures/*.gpx` — 15 onX/sort fixtures. These were excluded by `.gitignore` until
  2026-08-29; if 12 tests fail on a machine, check they are actually present and tracked.
- `tests/output/` is stale output from `scripts/test_edge_cases.py` (untracked since
  2026-08-30). It is not a fixture and no test reads it. Don't use it as an expectation
  baseline.

## Writing tests

TUI tests drive the real Textual app through `tests/tui_harness.py` + textual's `Pilot`.

**Never wrap an interaction or assertion in `try/except Exception`.** 35 existing TUI tests do
this and then assert nothing, so they pass unconditionally — 15 of them are in `tui_harness.py`
itself, which every TUI test inherits. A green TUI suite is therefore weak evidence.

If an interaction is genuinely flaky, `pytest.skip` it with a reason. Don't swallow.

When debugging a TUI failure, remember the production code swallows too: 251 `except Exception:
pass` blocks live in `cairn/tui/`. Neutralize the swallowing along the suspect path before
concluding the code is fine.

## Coverage gaps worth knowing

`core/preview.py` 16%, `tui/edit_screens/modals.py` 17%, `commands/convert_cmd.py` 36%,
`ui/interactive.py` 20%. `core/preview.py` is the meaningful one — 1946 lines on the primary
user path. `convert_cmd` matters less; that command is registered `hidden=True`.

Full analysis: `docs/CODEBASE_AUDIT_2026-08-29.md`.
