# Cairn UX audit — 2026-08-29

Companion to `CODEBASE_AUDIT_2026-08-29.md`. That one is about the code; this one is about the
person using it. Everything here was verified by driving the real app (`Textual.Pilot`) or by
running the real CLI against the committed fixtures — not by reading code and guessing.

---

## Part 1 — What is this project actually for?

Stripping away the implementation, Cairn exists because of one asymmetry:

> **Map platforms let you export your data, but not your *thinking about* the data.**

A CalTopo map isn't a bag of coordinates. It's coordinates plus a judgement layer: this is the
water source, that's the avalanche path, these six are camps, the red ones are the bail-out
routes. GPX and GeoJSON move the coordinates. Everything that made the map *worth making* —
icons, colors, folders, notes — is what falls on the floor. CalTopo's own docs admit it: *"GPX:
This is a commonly used file type, you lose line and marker style, and folder organization."*

**So the product is not a file converter. It is a judgement-layer preserver.** Every design
decision should be tested against that sentence. It explains why the editing step exists at all,
and why "1:1 mapping, we don't filter anything" is the right stance.

It also sets the bar for success, which is not "the file imported." It is:

> The user opens onX, and their map looks and behaves like the one they built in CalTopo.

### Who is on the other end

Backcountry hikers, climbers, hunters, skiers, SAR volunteers. People who chose CalTopo because
it's the serious tool, and who are now standing in a parking lot with one bar of signal. **Most
of them are not developers.** That single fact should govern the roadmap harder than anything in
the backlog, and it is the lens for Part 3.

### The strategic tension

Two goals are quietly fighting:

| | Wants |
|---|---|
| **"Faithful migration"** (README) | Automatic, invisible, one command, no decisions |
| **"Preview + batch edit"** (the actual feature set) | Deliberate, interactive, many decisions |

Both are real, but they are different products, and today the tool makes *everyone* walk the
interactive path. A user with a clean CalTopo GeoJSON where every icon maps cleanly should never
see an editor. A user importing a bare GPX with no metadata needs one badly. **The tool should
detect which case it's in and behave accordingly** — see Part 4.

## Part 2 — What actually happens today (measured)

### 2.1 The CLI, end to end

Run against the committed fixtures. Verbatim observations:

**GPX input was documented but rejected.** `README.md:59` says "Cairn now supports CalTopo GPX
exports as input," with a whole fidelity table beneath it. But `cairn migrate onx
tests/fixtures/bitterroots/bitterroots_subet.gpx` returned:

```
Expected a .json or .geojson file: .../bitterroots_subet.gpx
```

`parse_caltopo_gpx` existed, worked, was tested — and had exactly one caller in the whole
codebase: `cairn/tui/app.py:2265`. The feature shipped in the TUI and in the README, and never in
the CLI. **Fixed in this pass** (see Applied); `cairn migrate onx <file>.gpx` now works and warns
about what GPX cannot carry.

**`--no-interactive` prompts anyway, then aborts.**
```
$ cairn migrate onx ... --no-interactive
Ready to generate new map? [Y/n]: Aborted.
```
The flag's own help text says "Force interactive prompting even when stdin is not a TTY." It does
not suppress prompts. This is item 2 of 3 in `Instructions for agent.md`'s December bug list
("Medium: `--no-interactive` flag not fully respected") — still open eight months later, and it
means **Cairn cannot currently be scripted or run in CI.**

**"Order confirmed (--yes flag)" prints for a flag that does not exist.** `cairn migrate onx`
has no `--yes`. The string is hardcoded. It also prints twice, sandwiching a summary block that
is itself printed twice — once before the confirm, once after.

**The success message wraps into gibberish:**
```
✔ SUCCESS Data written to
/private/tmp/claude-501/-Users-scott--code-cairn/cd7217cc-5a36-4d10-9115-ec719bc
0d6f1/scratchpad/e2e/from_json
```
Rich is hard-wrapping a path mid-character. The one piece of information the user needs at the
end — *where are my files* — is the one rendered unusable. (Compare TODO.md: "Export Complete
screen should show `File written to:`".)

**The `<desc>` field is a debug dump.** This is the most damaging finding in the CLI, because it
is what the user actually sees in onX. Every waypoint's description arrives as:

```xml
<desc>name=Camp spot
notes=
id=cc734abf-b953-48d7-a3f9-f93825ed0684
color=rgba(0,0,0,1)
icon=Camp</desc>
```

The user's actual note is the empty `notes=` line. The other four lines are internal state — a
UUID, an rgba string, and two values already carried in the `<onx:>` extensions right below.
TODO.md already calls this out. **It directly contradicts the product thesis**: the tool that
exists to preserve the judgement layer is burying the user's own words in machine output.

### 2.3 Three help systems that disagree

The same shortcut list is rendered **twice on every screen** (footer at `widgets.py:159-162` and
sidebar at `app.py:2038-2043`, the latter eating 25% of the width), and a **third** independently
maintained copy lives in `modals.py:74-138`. They disagree:

- `t` (focus table) — bound globally, in the help modal, never in the footer.
- `Ctrl+A` — footer says "Toggle all", help says "Select all". It toggles.
- `Ctrl+N` — globally bound and destructive; in neither.
- `Ctrl+P` — Textual's command palette, undocumented and inescapable.
- Help says `c` = "Change directory/prefix"; `SaveTargetOverlay`'s own docstring says the prefix
  feature was removed.
- The file browser hint says `Space: expand/collapse`. Verified: Space does nothing there.

### 2.4 Developer vocabulary in the user interface

`"CalTopo → OnX (TUI v1)"` (`app.py:423`) · `"This TUI currently supports…"` (`app.py:2861`,
`file_browser.py:202` — and it's factually wrong, GPX works) · `"(tree mode)"` (`app.py:2034` —
that's an **A/B-test flag name** on screen) · `"records"` (`app.py:1821`) · `"override"`
(`overlays.py:790`) · `"unmapped symbols"` (`app.py:2293`) · `"Mappings are saved to

## Part 3 — The friction that actually decides adoption

Before any TUI polish, the honest ranking of what stops a hiker from using this tool:

**Tier 0 — they never get to the TUI at all.** Today's README asks the user to install `uv`,
`git clone` a repository, run `uv sync`, and then `uv run cairn tui`. For a non-developer that is
not a high bar, it is a wall. No amount of TUI refinement matters upstream of this. Distribution
recommendation is in `docs/DISTRIBUTION_2026-08-29.md`.

**Tier 1 — the output is wrong in a way they can see.** The `<desc>` debug dump lands in every
waypoint in onX. That is the first thing they'll notice after a "successful" migration.

**Tier 2 — the tool loses their work.** Esc quits after export; `Ctrl+N` wipes edits; export
overwrites silently; there's no undo.

**Tier 3 — the tool feels broken.** Search that accepts one character; Enter that does nothing on
the Folder step; 5.8-second freezes; the screen corrupting mid-export.

**Tier 4 — the tool is unclear.** Vocabulary, duplicated help, no folder orientation, no output
path.

Ordering matters: fixing Tier 4 while Tier 0 stands means polishing a door nobody can reach.

## Part 4 — Design direction

### 4.1 Make the easy case easy (biggest single UX win)

Today every user walks the full wizard. Most shouldn't have to. Cairn already has the information
to decide, at parse time:

- Every symbol maps cleanly, colors present, folders present → **nothing to decide.** Print a
  summary, write the files, done. One command, no screens.
- Unmapped symbols, or a GPX with no metadata at all → **there are decisions to make.** Open the
  editor, and open it *on the things that need attention*, not on the full list.

This turns "preview and edit everything" from a mandatory tollgate into an escalation. It also
resolves the strategic tension in Part 1 without having to choose a side.

### 4.2 Wizard → workspace

The six-step linear wizard (`Select_file → List_data → Folder → Routes → Waypoints → Preview`) is
the wrong shape for an editing tool. Evidence it's fighting itself: Folder is skipped
conditionally; Waypoints is skipped but still checkmarked; Routes is *deliberately* never skipped
"because tests rely on deterministic Enter progression" — the state machine is being shaped by
the test suite rather than the user. And multi-folder mode loops the same two screens N times
with no indication of where you are.

A persistent two-pane workspace — folder/feature tree on the left, detail and edit on the right,
with export as an action rather than a terminal step — removes the skip logic, the loop, the
orientation problem, and the "which step am I on" bookkeeping in one move. Concrete patterns and
a cost estimate are in `docs/TUI_RESEARCH_2026-08-29.md`.

### 4.3 Bulk editing is the actual killer feature

It's the top item in the project's own backlog and the stated reason the tool exists
("select multiple waypoints known to be water → Name: Water, Icon: Water, Color: Blue. Making
bulk updates in onX is either not possible or very difficult"). It is also the thing the TUI does
worst: multi-select works, but the only bulk operation is "give everything the same literal
name." Prefix/suffix exists in the legacy CLI and never made it across.

What it needs: filter-then-select-all ("select every waypoint matching `water`"), prefix/suffix
and find-replace rename, a preview of the resulting names before committing, and undo.

### 4.4 Rules to hold the line

1. **Never show a key that doesn't work** (Space on the file browser) and never bind a
   destructive key that isn't shown (`Ctrl+N`).
2. **One source of truth for shortcuts.** Derive footer, sidebar and help from the same
   structure. Three hand-maintained copies is why they disagree.
3. **`Esc` always means "close the thing in front of me."** Never "quit", never "rewind a step
   behind a dialog you can't see past."
4. **Confirm by blast radius, not by field.** 500 icon changes deserve a prompt more than 2
   renames do.
5. **Always show where the files went.** Full path, unwrapped, at the end.
6. **Pre-fill inputs with the current value.** Editing is not retyping.
7. **Speak the user's language.** They have waypoints and folders, not records, overrides,
   unmapped symbols, tree mode, or a TUI.
8. **Never let the UI fail silently.** 264 bare `except: pass` blocks in `cairn/tui/` mean a
   crash and a no-op look identical from the user's chair.
