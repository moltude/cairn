# Generic GPX (1.0, 1.1, routes, Garmin and gpx_style extensions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any GPX 1.0 or 1.1 file (waypoints, routes, tracks) opens with what its schema and the two common style extensions say: names, notes, symbols, colours and full routed shape.

**Architecture:** All changes are in the generic (non-onX) behaviour of `cairn/io/onx_gpx.py` and in `cairn/io/document_adapter.py`. onX's own extensions keep priority, so onX files are unchanged. CalTopo GPX keeps its own reader.

**Tech Stack:** stdlib `xml.etree`.

**Spec:** [`2026-10-23-input-formats-standards.md`](2026-10-23-input-formats-standards.md) (survey rows GPX 1.0, 1.1, Garmin v3, gpx_style; Decisions 1–2; Review Focus 1, 4). Requires S1 and S2 merged.

## Element → Cairn mapping (what this plan makes true)

| GPX element | Cairn |
|---|---|
| root namespace `…/GPX/1/1` or `…/GPX/1/0` | Both read; every `gpx:` lookup uses the root's namespace. |
| `wpt` `name`; `desc`, else `cmt` | Title; notes. (`desc` is for the user, `cmt` for the GPS, so `desc` wins.) |
| `wpt/sym` | `marker-symbol` → the symbol → keyword resolver. Garmin symbol names (the de-facto vocabulary the XSD defers to: "as displayed on the GPS") get mappings in `cairn/data/icon_mappings.yaml`. |
| `wpt/ele` | Kept (existing). |
| `wpt` `time`, `type`, `link`/`url`, `src`, `fix`…`dgpsid`, `gpxx:WaypointExtension` | Ignored. |
| `rte` `name`, `desc`/`cmt` | Title; notes. |
| `rtept` lat/lon/ele, then each `gpxx:RoutePointExtension/gpxx:rpt` | Line points in document order; an `rpt` equal to the next `rtept` is skipped. |
| `rtept` `name`/`sym` | Dropped (Decision 1). Documented. |
| `trk/trkseg/trkpt` | One line; segments joined in order (Decision 2). Time kept (existing). |
| Line colour, first found: onX `color` > `gpxx:RouteExtension`/`TrackExtension` `DisplayColor` (`Transparent` = none) > `gpx_style:line/color` (`RRGGBB`) | `stroke`, then onX nearest-colour (existing rule). |
| `gpx_style:line/width` (mm), `pattern` | Ignored (onX has two weights; a millimetre-to-weight rule would be invented). |
| `rte/type`, `trk/type` | onX semantics only when the desc block carries an onX `id=` (existing rule); otherwise ignored. |
| GPX 1.0 extensions: foreign elements as direct children (no `<extensions>`) | Colour lookup searches the element's direct children **and** its `<extensions>`. |
