# CSV Waypoints Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A spreadsheet of waypoints saved as CSV opens as one folder of pins, recognised by the most widely used column vocabulary rather than any one app's export.

**Architecture:** One reader, `cairn/io/csv_waypoints.py`, text → `ParsedData` (one folder named after the file), routed like the CalTopo paths (origin `None`), so icons and colours use the existing symbol/keyword and colour rules. Detection is a new `CSV` kind in `input_check`, tried only after JSON and XML have been ruled out.

**Tech Stack:** stdlib `csv`.

**Spec:** [`2026-10-23-input-formats-standards.md`](2026-10-23-input-formats-standards.md) (survey row CSV; Decisions 1 and 4). **Gated on Decision 1.** Requires S2.

## Standard used

No geospatial CSV standard exists. Structure follows **RFC 4180** (quoted fields, embedded commas/newlines, `""` escapes). Column names follow **GPSBabel `unicsv`**, the broadest published vocabulary, case-insensitive, with `_` and space treated alike, plus the GDAL convention of a `WKT` column for points.

| Role | Accepted headers | Notes |
|---|---|---|
| lat | `lat`, `latitude`, `y`, `y_pos` | Decimal degrees, −90…90. |
| lon | `lon`, `long`, `lng`, `longitude`, `x`, `x_pos` | Decimal degrees, −180…180. |
| hemisphere | `n/s`, `e/w` | `s`/`w` negates a positive value. |
| geometry (alt.) | `wkt` | `POINT (lon lat)` only; used only if there is no lat/lon pair. |
| name | `name`, `title`, `label` | |
| notes | `desc`, `description`, `notes`, `comment` | Several present → joined with a blank line, in that order. |
| symbol | `icon`, `symb`, `symbol`, `sym` | Into the resolver as the symbol. |
| colour | `color`, `colour` | `#RRGGBB` or a CSS name → nearest onX colour. Not in unicsv; a common spreadsheet column. |
| elevation | `ele`, `alt`, `altitude`, `height`, `z` | Metres; a `ft`/`feet` suffix in the header converts (unicsv rule). |
| everything else | — | Ignored; listed in the load result as `"ignored_columns"`. |

Delimiter: tab if the header has a tab (the unicsv rule); otherwise `,` or `;`, whichever splits the header into more fields. UTF-8 BOM stripped (GDAL behaviour). Decimal comma (`46,1` under `;`) → refused (Decision 4).

- Modify: `cairn/io/input_check.py` (`CSV = "csv"`; `_EXTENSIONS[CSV] = (".csv", ".tsv", ".txt")`; the `detect` branch for non-JSON/XML text calls `looks_like_csv`), `web/bridge.py` (`_ROUTE_CSV`, `_route`, `_read_one`, `_EXT[CSV] = ".csv"`; the not-a-map sentence lists CSV), `web/index.html` (`accept`, drop-sub), `web/app.js` (`fileTitle` regex), `cairn/io/kmz.py`'s Excel sentence (if not already "Save it as CSV")
- Test: `tests/test_csv_waypoints.py`

**Interfaces:**
- Produces:
  - `HEADER_ALIASES: dict[str, tuple[str, ...]]`: the table above.
  - `MAX_CSV_ROWS = 3000`.
  - `looks_like_csv(text: str) -> bool`: true when the header (after the delimiter rule) contains a lat and a lon alias, or `wkt`.
  - `parse_csv_waypoints(text: str, folder_name: str) -> ParsedData`: waypoint features with `title`, `description`, `marker-symbol`, `marker-color`; coordinates `[lon, lat]` or `[lon, lat, ele]`. Rows with blank or out-of-range coordinates are skipped and counted.
  - The load result gains `"skipped_rows": int` and `"ignored_columns": list[str]`; `renderSourceNotice` in `app.js` shows them when non-zero/non-empty.

Refusal sentences (one each): no lat/lon or WKT column ("Cairn couldn't find latitude and longitude columns in X. It looks for headers named lat/latitude/y and lon/longitude/x."); decimal comma; more than `MAX_CSV_ROWS` rows; zero valid rows.
