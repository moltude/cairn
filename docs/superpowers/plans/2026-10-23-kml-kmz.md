# KML (generic) and KMZ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any KML 2.2/2.3 file (and its KMZ wrapper) opens with its folders, its line/area/pin colours and all its geometry, by the OGC/Google rules rather than by any one exporter's habits.

**Architecture:** Generic KML moves from `onx_kml.py` to the style- and folder-aware `caltopo_kml.py`, whose gaps against the spec are then closed. KMZ is an unwrap step in front of `guard_input`: it yields KML text, which takes the normal guard → detect → route path.

**Tech Stack:** stdlib `zipfile`, `base64`, `xml.etree`; `web/app.js` for the binary read.

**Spec:** [`2026-10-23-input-formats-standards.md`](2026-10-23-input-formats-standards.md) (standards survey rows KML, `gx:`, KMZ; Global Constraints; Review Focus 2, 3, 5). Requires S1 and S2 merged.

## Element → Cairn mapping (what Task 1 makes true)

| KML element | Cairn |
|---|---|
| `Document`, `Folder` (any depth) | Folder; nested → `"Parent / Child"` (existing `caltopo_kml` rule). No folder → one folder named after the file. |
| `Placemark/name`, `description` | Title; notes (HTML stripped, existing). |
| `Point` | Waypoint. |
| `LineString`, `gx:Track`/`Track`, each `Track` of a `MultiTrack` | Line. A track's `gx:coord` is "lon lat alt", space-separated; `when` is kept as point time when the counts match, otherwise dropped (geometry kept). |
| `LinearRing` as a Placemark geometry | Line (closed). |
| `Polygon` (outer + inner) | Area (existing, holes kept). |
| `MultiGeometry` | Flattened (existing). |
| `Style` inline > `styleUrl #id` → `Style` or `StyleMap` → `Pair key=normal` → `styleUrl` **or inline `Style`** | `IconStyle/color`, `LineStyle/color,width`, `PolyStyle/color` (aabbggrr), via the existing `kml_color`. |
| `styleUrl other.kml#id` (external) | Ignored → defaults. Documented. |
| `IconStyle/Icon/href` (non-CalTopo) | Basename without extension becomes the symbol (`…/shapes/campground.png` → `campground`) and goes through the normal symbol → keyword resolver. |
| `ExtendedData`, `TimeStamp`, `TimeSpan`, `Region`, `LookAt`, `Camera` | Ignored. |
| `NetworkLink`, `GroundOverlay`, `ScreenOverlay`, `PhotoOverlay`, `Model` | Ignored; reported in the load result as `"ignored": {"GroundOverlay": 2, …}` so the UI can say so. |
| Namespaces `http://www.opengis.net/kml/2.2`, `http://earth.google.com/kml/2.0`–`2.2`, `gx:` | All read (`_ln` drops the namespace). |

### Task 2: KMZ (and the `.xlsx` refusal)

**Files:**
- Create: `cairn/io/kmz.py` (`# Web engine:` header)
- Modify: `cairn/io/input_check.py` (`_EXTENSIONS[KML]` gains `".kmz"`), `web/bridge.py` (`load_files` entry shape), `web/app.js` (`handleFiles`; the `fileTitle` regex gains `kmz`), `web/index.html` (`accept`, drop-sub text)
- Test: `tests/test_kmz.py`, `tests/web/test_web_app.py`

**Interfaces:**
- Consumes: Task 1's routing (via `detect` on the extracted text).
- Produces:
  - `MAX_KMZ_BYTES = 64 * 1024 * 1024`. The archive arrives whole in memory anyway; images inside are skipped.
  - `is_zip(data: bytes) -> bool`: `data[:4] == b"PK\x03\x04"`.
  - `kml_from_kmz(data: bytes, filename: str) -> str`: `ValueError` sentences for every refusal.
  - `load_files` entries are `{"name","text"}` **or** `{"name","b64"}`. `b64` is decoded; if `is_zip`, `kml_from_kmz` runs; the text then takes `guard_input → detect → _route` unchanged. Name and stem stay the `.kmz` filename.

Entry choice, from Google's KMZ page ("the first .kml file"; with several, "you cannot be sure which"): `doc.kml` at the root; else the only root-level `*.kml`; else the only `*.kml` anywhere; else refuse ("… holds N KML files and no doc.kml, so Cairn can't tell which one is the map.").

Safety: read the chosen entry through `zf.open()` in 1 MiB chunks and stop at `input_check.MAX_XML_INPUT_BYTES + 1`; never trust `ZipInfo.file_size`. Over the cap → the same size sentence `guard_input` gives. Encrypted entry, `BadZipFile`, a nested `.kmz`, invalid UTF-8 → one sentence each. A zip with `[Content_Types].xml` and `xl/workbook.xml` → "This is an Excel workbook. Save it as CSV, or export the map as GPX or KML, and open that." (Drop "as CSV" if the CSV plan is declined.)

JS: `handleFiles` reads `await f.arrayBuffer()` and checks the first 4 bytes for `PK\x03\x04` (magic, not extension). Zips are sent as `{name, b64}`, built chunkwise (no spread of a large array into `String.fromCharCode`). Everything else goes as `{name, text}` via `TextDecoder`.
